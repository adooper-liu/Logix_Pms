# UI 信息架构与可视化选型

本文回答三个问题：每个页面**为谁解决什么问题**、页面上的元素**是什么关系**、
以及这类信息**用什么可视化最合适**。改版时先看这份文档，再动代码。

## 一、总体原则

1. **一页一个主问题**。页面首屏只回答一个决策问题，其余信息降级为次级区域或页签。
2. **三层信息**：全局结论 → 当前对象 → 明细。先给判断，再给依据，最后给操作。
3. **入口必须显性**。可点击的元素要有视觉提示（箭头、hover、按钮），跳转时带上筛选条件。
4. **一种信息只用一种主可视化**。表格负责比较，卡片负责浏览，进度条负责完成度，
   雷达负责四维均衡，折线负责趋势，树/导航负责层级。
5. **颜色只表达状态**。颜色来自主题令牌，不承担装饰；新增主题只改变量，不改组件。

## 二、跨页面关系

```text
管理驾驶舱（全局健康 + 入口）
  ├─→ 流程地图（结构定位）──→ 流程设计器（建模与测算）
  ├─→ 流程项目组合（执行跟踪）──→ 项目详情（KPI/步骤/甘特）
  ├─→ 运营监控（结果与异常）──→ 异常台账 / KPI 明细
  └─→ 知识库（经验复用）──→ 工具箱（方法选择）

五阶段工作流（方法说明）──→ 工具箱
工具箱 ──→ 设计器（建议里的工具可以直接打开）
工作流（24 步要求产出什么）──→ 交付物与模板库（产出是否齐、哪一版）
交付物与模板库（标准文件=唯一源）──→ 流程设计器（模型改了就该产生新版本）

PCF 分类框架（行业参照系）──→ 流程地图（公司流程与分类建立映射）
流程地图（公司架构）  ←  PCF（行业分类）   两者是映射关系，不是层级关系

组织与人员（主数据）──→ 交付物与模板库（继承范围）、设计器（分派与岗位）
```

判断一条链接是否该存在：点击后用户是否**少做一次选择**。如果只是换一个页面继续找，
那它就不是入口，应该合并或删除。

三条关系需要特别说明，因为它们容易被画成错的形状：

1. **流程地图与 PCF 是映射，不是层级**。公司架构 L1–L4 是自己的树，
   PCF L1–L5 是行业词典，两边通过 PCF ID 对应。一个是「我们怎么组织」，
   一个是「行业怎么分类」，不要画成上下级，也不要互相替换。
2. **交付物与模板库是标准文件和项目之间的桥**。没有它，
   「标准文件」和「项目产出」就是两堆互不相干的文件，「追溯」无从谈起。
3. **组织与人员是主数据，不是业务页面**。它不产生流程、不产生文档，
   只提供归属与继承范围——所以它放在导航的「系统」分组最后一位。

## 三、逐页分析

以下 13 节与导航栏的 13 个页面一一对应。

### 1. 管理驾驶舱

- **主问题**：今天最需要我关注什么？
- **元素与关系**：
  - 4 个主指标（在办项目、待改善流程、未闭环异常、平均目标改善）是**结论层**。
  - 五阶段健康度是**过程层**，说明项目卡在哪个阶段。
  - 风险提醒是**行动层**，把健康度低的流程和未闭环异常放在首屏右侧。
  - 方法论分布是**结构层**，只保留一条堆叠条，不占独立卡片。
  - 「改善优先级 / 重点项目」是**行动层**：左侧回答「该改什么」（候选流程），
    右侧回答「正在做什么」（在办项目），左右相邻，形成从候选到立项的阅读顺序。
- **价值判定**：指标卡必须可点击，否则只是数字墙；阶段行必须能跳到对应阶段的项目；
  方法论图例必须能跳到对应方法的项目；优先级行必须能定位到地图中的流程。
- **可视化选型**：KPI 数字卡（结论）+ 水平进度条（阶段）+ 堆叠条（构成）+ 表格（候选/项目）。
  不用仪表盘图——没有统一目标值，指针没有意义。
- **已落地**：4 个主指标卡、阶段行、方法论图例、风险提醒、优先级行与项目行均可点击并带筛选；
  健康预警只保留 Top 4，候选与项目各保留 Top 5。

### 2. 企业流程地图

- **主问题**：我的流程架构长什么样，这条流程处在哪一层、上下文是什么？
- **元素与关系**：
  - 左侧架构导航树是**层级入口**，只展开当前路径，避免一次铺开 148 个节点。
  - 中间当前层列表是**主内容**，一行一个流程，带健康度、痛点、优先级和下钻入口。
  - 对标覆盖是**可选参照系**，切换 SCOR/APQC 只换参照树，不改公司架构。
- **价值判定**：树负责「在哪」，表格负责「是什么」，对标负责「对应行业哪一类」。
  跨层排序不属于地图的职责，已统一收敛到驾驶舱「改善优先级」，避免同屏两套榜单。
- **可视化选型**：树 + 表格 + 热力标签。层级关系用树，不用饼图；
  优先级用颜色标签和分数，不用 3D 图。
- **后续可选**：L1 概览的 treemap（面积=流程数或综合得分）可以更直观，
  但必须与表格二选一，不能同屏堆两套层级视图。

### 3. PCF 分类框架

- **主问题**：这类工作在行业分类里叫什么、官方定义是什么、对应的指标有哪些、
  我们公司覆盖了多少？
- **元素与关系**：
  - 左侧分类树（L1–L5 可展开）是**层级入口**，支持按编码、中文名、英文名搜索；
    搜索命中时会自动展开祖先链并保留父级上下文，不会只给一个孤立的命中项。
  - 右侧详情面板是**主内容**：面包屑 → 中英文名 → PCF ID → 官方定义 →
    公司流程覆盖数 → 该类别的 PCF 指标。
  - 顶部 L1–L5 五张说明卡是**字典说明**（每个层级是什么、当前有多少个），
    不是数据图表，作用是先教用户怎么读这棵树。
  - 框架下拉切换的是 **APQC PCF 及其行业变体**——换参照系，不换公司架构。
- **价值判定**：这页是**参照系**，不是作业对象。
  它产出的是"认知"（这个词对应什么、指标怎么挂），不是"编辑"，
  所以它应该**只读 + 能跳到流程地图**，不应该提供创建流程的操作。
  页面上要反复讲清的一件事是：**PCF 是分类，不是流程图**——
  它不含先后顺序、分支和事件触发，流程语义由 BPMN 设计器维护。
  同理，PCF ID（5 位）才是跨版本稳定键，Hierarchy ID 会因行业元素插入而漂移，
  不能当稳定标识用。
- **可视化选型**：树 + 详情面板。层级关系用树，不用饼图也不用 treemap；
  指标用列表，不用雷达。理由是这页要回答的是"它是什么"，
  而"是否均衡"是监控页的问题，不要把雷达图搬到这里。

### 4. 五阶段标准工作流

- **主问题**：当前阶段该做哪几步、每步用什么方法、交付什么？
- **元素与关系**：
  - 阶段切换条是**进度/层级入口**。
  - 单阶段步骤卡片是**主内容**，每张卡只保留步骤名和交付物。
  - 方法论匹配是**决策辅助**，放在独立页签，避免和步骤说明抢注意力。
- **价值判定**：24 个步骤一次全铺会让人失去焦点；一次只看一个阶段，符合执行节奏。
- **可视化选型**：阶段 stepper + 步骤卡片。阶段之间是顺序关系，用带颜色的阶段标签表达；
  不需要甘特图——这是标准模板，不是排期。

### 5. 流程项目组合

- **主问题**：哪些项目在推进、哪些卡住、资源花在哪？
- **元素与关系**：
  - 4 个汇总指标是**组合结论**（总数/进行中/已结项/平均进度）。
  - 三个筛选是**切片维度**（方法/阶段/状态）。
  - 表格是**主内容**，一行一个项目，点击进入详情。
- **价值判定**：筛选器应该和汇总指标同处页头，表格独立成卡；
  项目行必须整行可点，不能只让「详情」按钮可点。
- **可视化选型**：表格是正确选择。项目数量在几十条以内，表格比卡片密度高、可比性强。
  后续如果项目超过 50 条，再考虑加一个「进度 × 预算」气泡图作为分析视图，而不是替代表格。

### 6. 方法论工具箱

- **主问题**：我遇到的问题该用哪个工具？
- **元素与关系**：
  - 「按问题找工具」是**主入口**，应该比工具列表更靠前。
  - 分类标签是**浏览入口**，一次只展示一个类别的工具。
  - 工具卡片是**浏览内容**，摘要限制两行，点开看标准操作与误用。
- **价值判定**：搜索优先于分类；工具卡只负责「让我决定要不要点开」，
  不负责讲完整个方法。
- **可视化选型**：分类标签 + 卡片。工具之间是并列关系，不需要图表。

### 7. 交付物与模板库

- **主问题**：这一步该产出什么、现在产出到哪一版、能不能追溯回来源？
- **元素与关系**：
  - 四个页签对应**四类不同性质的资产**，这是本页最重要的区分：
    - **流程标准文件**是**唯一源**（源文件本身，带组织 / 变体 / 有效版本 /
      升级变基 / 复制晋升）；
    - **项目交付物**是**实例**（某个项目里对标准文件某一版的引用与实际产出）；
    - **工具模板库**是**按工具维护的预制模板**（还没落到具体项目）；
    - **基线与审计**是**治理视图**（当前基线是什么、有哪些待处理发现项）。
  - 项目交付物页签的顺序是「选项目 → 4 个汇总指标 → 交付物清单」：
    汇总指标（总数 / 已生效 / 必需项未产出 / 已生效占比）回答"这个项目齐不齐"，
    清单逐行标出**当前版本与状态**，回答"具体缺哪一项"。
  - 状态链是 DRAFT → IN_REVIEW → APPROVED → EFFECTIVE → SUPERSEDED，
    中文标签由后端下发；前端只负责色调，不维护文案。
- **价值判定**：**追溯链必须闭合**——
  标准文件（源）→ 变体（组织差异）→ 项目交付物引用的是哪一版。
  任何一环断开，"项目交付物齐不齐"就变成无法回答的问题。
  因此页面入口要给出「查看 24 步标准工作流」的回指，不能让人在这页里失去上下文。
- **可视化选型**：表格 + 版本链 + 状态标签。版本关系是**链**不是网，
  不画关系图；变体继承用文字路径表达。汇总指标用数字卡（4 个，纯计数，无目标值）。
- **已知缺口**：项目交付物列表目前一次性拉 `page_size=200`，
  尚未接入分页——项目数上量后会出现「列表截断但看不出来」的问题，
  与知识库是同一类问题（见 [docs/frontend-architecture.md](frontend-architecture.md) §2.4）。

### 8. 流程设计器

- **主问题**：这条流程长什么样、时间花在哪、该改哪里？
- **元素与关系**：
  - 流程选择器 + 操作按钮是**对象与动作**。
  - 页签主链：**模型 → 测算分析 → 权责 → 变更**（变更靠发布门禁，不插在分析与权责之间）。
  - 模型页是 **bpmn-js 专业画布**：调色板、折点、上下文菜单、撤销/重做、复制粘贴、
    泳道与自动布局；双击元素直接改名，单击只选中。
  - 选中元素后右侧滑出**属性栏**：节点（名称/类型/泳道/负责人/PMS 指标/分派与 SLA）、
    连线（标签/条件/概率）、泳道（改名、新增）、流程（泳道概览）；侧栏可收起，
    「校验」页签显示中文化的 bpmnlint 结果。
  - 画布工具栏单行分组：**视图**（布局/适应/全屏）→ **校验** → **分析**
    （模拟/决策/补偿/评论）→ **编辑**（泳道）→ **帮助**；状态在右侧；
    属性走右侧折叠条；长操作说明收进 `?`，不占工具条。图形修改自动保存草稿。
  - 页头分层：①身份+流程选择/去执行 ②状态条（当前草稿 / 运行时 / 下一步）
    ③**页签（左，看哪里）+ 流程动作（右，对流程做什么）** 同层并置。
    页签主链：模型 → 测算分析 → 权责 → 变更；动作：生命周期 → 治理 → 导入导出
    （「重新测算」只在测算页出现；门禁未过时才显示「去批准变更」）。
    「版本历史」打开版本列表、差异对比和回滚。发布前改动只进草稿，不直接影响新实例。
  - 指标 + 建议是**解释层**，必须和模型分开，否则同屏信息过载。
- **价值判定**：默认看模型；需要解释时再切到测算分析；定事项 A/R 看权责；过门禁发布看变更。
  节点徽标只标异常，不给每个节点画进度条；校验错误阻止保存，警告允许草稿继续；
  发布是显式动作，避免「保存即上线」。
- **可视化选型**：泳道图 + 横向指标条 + 建议卡片。周期效率 PCE 用百分比，
  端到端周期/成本/移交次数只给数字——没有目标值就不画进度条，避免编造百分比。
- **BPMN 边界**：导出/导入结构子集（节点、连线、泳道、条件、坐标）；
  并行网关、子流程、边界事件明确拒绝，避免导入后运行语义错误。

### 9. 架构草图（独立 draw.io 白板）

- **主问题**：架构/汇报示意图画在哪，且不污染可执行流程模型？
- **元素与关系**：
  - 列表是**草图库**：标题、关联流程/项目、创建人、更新时间。
  - 「打开」进入 draw.io iframe；保存写回 mxfile XML，不进入 BPMN 设计器。
  - 视觉上刻意与流程设计器分开：草图没有发布/评审、没有执行语义。
- **价值判定**：自由画布用于沟通和汇报；可执行流程仍走 bpmn-js 设计器。
- **安全**：默认使用官方 embed，生产建议自托管 draw.io，避免草图外发。

### 10. 运营监控与 KPI
- **主问题**：运营结果是否达标，异常是否闭环？
- **元素与关系**：
  - 页签拆成**概览 / KPI 明细 / 异常台账**，分别回答「健康吗」「哪项差」「哪件事没闭环」。
  - 概览里四维卡片是**结论**，雷达是**均衡性**，趋势是**方向**，最弱 5 项是**行动清单**，
    异常概览是**待办**。
  - KPI 明细表负责完整数据与走势；异常台账负责处理动作。
- **价值判定**：雷达图只回答「四维是否均衡」；趋势图回答「在变好还是变差」；
  两者不能合并成一个图。KPI 表格和异常台账不应出现在概览首屏。
- **可视化选型**：雷达（四维）+ 折线（趋势）+ 迷你走势（单指标）+ 表格（明细）。
  概览的趋势线与雷达使用同一口径：先按维度平均，再对维度平均。

### 11. 流程知识库

- **主问题**：有没有可复用的案例、模板或标准？
- **元素与关系**：
  - 类型/标签/排序是**检索入口**。
  - 知识卡片是**浏览内容**，标题 + 两行摘要 + 类型/方法标签 + 热度。
  - 「按问题找工具」是**跨库入口**，放在列表之后，避免抢主内容。
- **价值判定**：知识条目是内容消费，不是流程执行；卡片比表格更适合浏览。
  摘要必须截断，详情里再展开全文。
- **可视化选型**：分类标签 + 卡片。后续条目增多时，再考虑加阅读量/时间的热力或排行榜，
  但不要用图表替代卡片。

### 12. 流程执行

- **主问题**：现在有哪些任务等我处理、实例卡在哪、依据哪一版模型启动的？
- **主路径**：认领/处理待办 → 填表单 → 推进节点；启动须基于**已发布**模型快照。
  改善项目进度不在本页维护（回「流程项目组合」）。
- **元素与关系**：
  - 页头**单层导航**：待办 | 实例 | 运行配置 | 集成（后两者仅管理角色），与标题、启动按钮同一行，少空白。
  - 上线路径（设计器 → 运行配置 → 启动 → 待办）只在**启动弹窗**可视化引导；页头用 `?` tip 说明，避免双层导航抢视线。
  - 默认落点仍是**待办**，范围默认**我的**；从设计器跳入带 process 时落到运行配置核对。
  - 待办范围用列表旁 **seg**（我的 / 公共 / 全部），不再用四张 KPI 卡；「全部」含他人在办，不等于我的+公共。
  - 页签角标：待办显示我的数量，实例显示**运行中**数量（不再用「运行中实例」卡片跳转）。
  - 「运行配置」**按流程各自一份**（非全局）：三列布局——左配置步骤引导、中单主题内容、右上下文。
    推荐顺序：选流程 → 节点分派 → 任务表单 → 时限与升级 → 就绪检查；一次只展示一个主题。
    「表单」= 节点待办输入字段模板（非 Excel/台账）；字段清单表格编辑，存 JSON。
    **分支路由以设计器出边为准**（运行匹配条件 + 默认流）；执行页只读展示模型出口，
    旧 process_rule 仅过渡兜底。改走法 → 回设计器 → 再发布。
    设计器节点「执行」页签与运行配置同口径：任务表单摘要 + 本节点出口 + 节点分派/时限；
    跳转带 `focus=forms|assign`。
  - 启动弹窗展示就绪清单：未发布为阻塞；未分派/未表单为建议项。
  - 实例表关键列：冻结版本、状态、当前节点业务名、处理人、时限/超期、发起信息。
  - 任务行是**行动单元**：可处理时统一「处理」；公共队列打开时自动接办（不再单独认领）。
  - 实例详情：版本、处理人/时限、配置快照、任务时间线；管理角色可挂起/恢复/取消；
    **已完成/已取消**可物理删除（确认后），日常清理优先「归档」；运行中不可删。
  - 集成页签是运维通道（入站/出站 Webhook），不与日常作业抢首屏。
- **价值判定**：任务队列优先；启动受发布门禁；配置只对管理角色；快照冻结防历史漂移。
- **可视化选型**：任务表格；实例表格 + 时间线弹窗；流程图仍在设计器。

### 13. 组织与人员

- **主问题**：组织层级与人员账号是否正确、归属是否有效？
- **元素与关系**：
  - 三个页签（组织架构 / 人员与角色 / 岗位）是**三类主数据**，不是三个功能入口。
  - 组织架构表是**层级列表**：用缩进表达父子关系，同行还要看编码、类型、
    完整路径、子节点数、启停状态、描述——是列比较，不是层级导航。
  - 人员表是**账号清单**，筛选维度是关键词 / 归属组织 / 角色 / 是否启用；
    归属组织不是显示字段，它决定标准文件与模板的**继承范围**。
  - 岗位是**执行位置定义**，供流程分派规则引用，与人员账号是两张主数据。
- **价值判定**：这页存在的理由不是"管理组织架构"，而是**给继承范围一个可信的来源**。
  组织编码错了，标准文件的集团→分公司继承就会落到错误的范围。
  所以组织编码与层级是必填、启停要有区分，不能和人员账号混在一张表里。
- **可视化选型**：表格 + 缩进表达层级。组织架构**不用树形控件**——
  需要横向比较的列（编码、路径、子节点数、启停）太多，树形控件放不下；
  层级关系用缩进 + 完整路径两列表达，比画树更易读。
- **权限**：仅 ADMIN 可见可写。非 ADMIN 进入时显示的是一张说明卡
  （"仅系统管理员可操作"），而不是 403 错误页——因为这是导航里的常驻入口，
  直接报错会让用户以为系统坏了；说明卡把"为什么不给看"讲清楚。

## 四、主题与视觉壳

- 所有颜色、圆角、阴影、间距都在 `web/css/base.css` 的 `:root` 令牌里。
- 组件与视图只允许 `var(--token)`；`tests/test_frontend_structure.py` 会拦截硬编码颜色。
- 主题切换由 `web/js/core/theme.js` 负责：新增主题 = 一组 `[data-theme]` 变量 + `THEMES` 登记。
- Canvas 图表通过 `cssVar()` 取色，切换主题时原地重绘，避免颜色与页面壳脱节。
