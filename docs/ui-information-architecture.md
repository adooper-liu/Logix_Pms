# UI 信息架构与可视化选型

本文回答三个问题：每个页面**为谁解决什么问题**、页面上的元素**是什么关系**、
以及这类信息**用什么可视化最合适**。改版时先看这份文档，再动代码。

## 一、总体原则

1. **一页一个主问题**。页面首屏只回答一个决策问题，其余信息降级为次级区域或页签。
2. **三层信息**：全局结论 → 当前对象 → 明细。先给判断，再给依据，最后给操作。
3. **入口必须显性**。可点击的元素要有视觉提示（箭头、hover、按钮），跳转时带上筛选条件。
4. **一种信息只用一种主可视化**。表格负责比较，卡片负责浏览，进度条负责完成度，
   雷达负责四维均衡，折线负责趋势，树/导航负责层级。
5. **颜色只表达状态**。颜色来自主题令牌，不承担装饰；新增主题只改变量，不改组件。

## 二、跨页面关系

```text
管理驾驶舱（全局健康 + 入口）
  ├─→ 流程地图（结构定位）──→ 流程设计器（建模与测算）
  ├─→ 流程项目组合（执行跟踪）──→ 项目详情（KPI/步骤/甘特）
  ├─→ 运营监控（结果与异常）──→ 异常台账 / KPI 明细
  └─→ 知识库（经验复用）──→ 工具箱（方法选择）

五阶段工作流（方法说明）──→ 工具箱
工具箱 ──→ 设计器（建议里的工具可以直接打开）
```

判断一条链接是否该存在：点击后用户是否**少做一次选择**。如果只是换一个页面继续找，
那它就不是入口，应该合并或删除。

## 三、逐页分析

### 1. 管理驾驶舱

- **主问题**：今天最需要我关注什么？
- **元素与关系**：
  - 4 个主指标（在办项目、待改善流程、未闭环异常、平均目标改善）是**结论层**。
  - 五阶段健康度是**过程层**，说明项目卡在哪个阶段。
  - 风险提醒是**行动层**，把健康度低的流程和未闭环异常放在首屏右侧。
  - 方法论分布是**结构层**，只保留一条堆叠条，不占独立卡片。
  - 重点项目是**下钻层**，最多 5 行，点击进入项目详情。
- **价值判定**：指标卡必须可点击，否则只是数字墙；阶段行必须能跳到对应阶段的项目；
  方法论图例必须能跳到对应方法的项目。
- **可视化选型**：KPI 数字卡（结论）+ 水平进度条（阶段）+ 堆叠条（构成）+ 表格（项目）。
  不用仪表盘图——没有统一目标值，指针没有意义。
- **已落地**：4 个主指标卡、阶段行、方法论图例、风险提醒、项目行均可点击并带筛选；
  健康预警只保留 Top 4。

### 2. 企业流程地图

- **主问题**：我的流程架构长什么样，哪一层/哪条流程最该改善？
- **元素与关系**：
  - 左侧架构导航树是**层级入口**，只展开当前路径，避免一次铺开 148 个节点。
  - 中间当前层列表是**主内容**，一行一个流程，带健康度、痛点、优先级和下钻入口。
  - 右侧/下方改善优先级是**跨层榜单**，回答「先看哪几条」。
  - 对标覆盖是**可选参照系**，切换 SCOR/APQC 只换参照树，不改公司架构。
- **价值判定**：树负责「在哪」，表格负责「是什么」，热度榜负责「先看谁」。
  三者职责不能互相替代。
- **可视化选型**：树 + 表格 + 热力标签。层级关系用树，不用饼图；
  优先级用颜色标签和分数，不用 3D 图。
- **后续可选**：L1 概览的 treemap（面积=流程数或综合得分）可以更直观，
  但必须与表格二选一，不能同屏堆两套层级视图。

### 3. 五阶段标准工作流

- **主问题**：当前阶段该做哪几步、每步用什么方法、交付什么？
- **元素与关系**：
  - 阶段切换条是**进度/层级入口**。
  - 单阶段步骤卡片是**主内容**，每张卡只保留步骤名和交付物。
  - 方法论匹配是**决策辅助**，放在独立页签，避免和步骤说明抢注意力。
- **价值判定**：24 个步骤一次全铺会让人失去焦点；一次只看一个阶段，符合执行节奏。
- **可视化选型**：阶段 stepper + 步骤卡片。阶段之间是顺序关系，用带颜色的阶段标签表达；
  不需要甘特图——这是标准模板，不是排期。

### 4. 流程项目组合

- **主问题**：哪些项目在推进、哪些卡住、资源花在哪？
- **元素与关系**：
  - 4 个汇总指标是**组合结论**（总数/进行中/已结项/平均进度）。
  - 三个筛选是**切片维度**（方法/阶段/状态）。
  - 表格是**主内容**，一行一个项目，点击进入详情。
- **价值判定**：筛选器应该和汇总指标同处页头，表格独立成卡；
  项目行必须整行可点，不能只让「详情」按钮可点。
- **可视化选型**：表格是正确选择。项目数量在几十条以内，表格比卡片密度高、可比性强。
  后续如果项目超过 50 条，再考虑加一个「进度 × 预算」气泡图作为分析视图，而不是替代表格。

### 5. 方法论工具箱

- **主问题**：我遇到的问题该用哪个工具？
- **元素与关系**：
  - 「按问题找工具」是**主入口**，应该比工具列表更靠前。
  - 分类标签是**浏览入口**，一次只展示一个类别的工具。
  - 工具卡片是**浏览内容**，摘要限制两行，点开看标准操作与误用。
- **价值判定**：搜索优先于分类；工具卡只负责「让我决定要不要点开」，
  不负责讲完整个方法。
- **可视化选型**：分类标签 + 卡片。工具之间是并列关系，不需要图表。

### 6. 流程设计器

- **主问题**：这条流程长什么样、时间花在哪、该改哪里？
- **元素与关系**：
  - 流程选择器 + 操作按钮是**对象与动作**。
  - 页签区分**模型**和**指标与建议**：先看图，再看测算。
  - 泳道图是**主内容**；节点上的等待、返工、瓶颈徽标是**诊断线索**。
  - 指标 + 建议是**解释层**，必须和模型分开，否则同屏信息过载。
- **价值判定**：默认看模型；需要解释时再切到指标与建议。
  节点徽标只标异常，不给每个节点画进度条。
- **可视化选型**：泳道图 + 横向指标条 + 建议卡片。周期效率 PCE 用百分比，
  端到端周期/成本/移交次数只给数字——没有目标值就不画进度条，避免编造百分比。

### 7. 运营监控与 KPI

- **主问题**：运营结果是否达标，异常是否闭环？
- **元素与关系**：
  - 页签拆成**概览 / KPI 明细 / 异常台账**，分别回答「健康吗」「哪项差」「哪件事没闭环」。
  - 概览里四维卡片是**结论**，雷达是**均衡性**，趋势是**方向**，最弱 5 项是**行动清单**，
    异常概览是**待办**。
  - KPI 明细表负责完整数据与走势；异常台账负责处理动作。
- **价值判定**：雷达图只回答「四维是否均衡」；趋势图回答「在变好还是变差」；
  两者不能合并成一个图。KPI 表格和异常台账不应出现在概览首屏。
- **可视化选型**：雷达（四维）+ 折线（趋势）+ 迷你走势（单指标）+ 表格（明细）。
  概览的趋势线与雷达使用同一口径：先按维度平均，再对维度平均。

### 8. 流程知识库

- **主问题**：有没有可复用的案例、模板或标准？
- **元素与关系**：
  - 类型/标签/排序是**检索入口**。
  - 知识卡片是**浏览内容**，标题 + 两行摘要 + 类型/方法标签 + 热度。
  - 「按问题找工具」是**跨库入口**，放在列表之后，避免抢主内容。
- **价值判定**：知识条目是内容消费，不是流程执行；卡片比表格更适合浏览。
  摘要必须截断，详情里再展开全文。
- **可视化选型**：分类标签 + 卡片。后续条目增多时，再考虑加阅读量/时间的热力或排行榜，
  但不要用图表替代卡片。

### 9. 流程执行

- **主问题**：现在有哪些流程在跑、哪些任务等我处理、流程走到哪了？
- **元素与关系**：
  - 「待办任务 / 流程实例 / 表单与规则」三个页签分别回答待办、历史和配置。
  - 统计卡（我的待办、公共队列、全部待办、运行中实例）是**入口**，点击切换列表筛选。
  - 任务行是**行动单元**：未指派显示「认领」，本人/管理员显示「处理」，其他人只读。
  - 完成任务时的表单字段来自节点表单定义；多分支节点显示下一步选择，规则命中时自动选择。
  - 实例详情是**时间线**：任务、处理人、完成时间、表单数据与流程变量。
- **价值判定**：任务队列优先于实例列表；配置只对管理角色可见；表单与规则随实例冻结，
  避免运行中改配置导致历史不一致。
- **可视化选型**：任务用表格（可批量扫读），实例用表格 + 时间线弹窗；
  不在这里放流程图，流程图属于设计器。

## 四、主题与视觉壳

- 所有颜色、圆角、阴影、间距都在 `web/css/base.css` 的 `:root` 令牌里。
- 组件与视图只允许 `var(--token)`；`tests/test_frontend_structure.py` 会拦截硬编码颜色。
- 主题切换由 `web/js/core/theme.js` 负责：新增主题 = 一组 `[data-theme]` 变量 + `THEMES` 登记。
- Canvas 图表通过 `cssVar()` 取色，切换主题时原地重绘，避免颜色与页面壳脱节。

## 五、后续优先级

1. **对标映射维护界面**：目前映射 CRUD 只有 API，流程地图只能看不能改。
2. **项目组合分析视图**：项目数量增长后，增加「进度 × 预算」气泡图作为表格的补充。
3. **流程地图 treemap**：如果需要在 L1 层一眼看出面积与热度，再引入；与表格二选一。
4. **前端事件委托**：去掉 `window` 上的几十个函数，降低后续改造成本。
