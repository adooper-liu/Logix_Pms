# 从 0 到 1 建一条流程：培训操作指南

> 适用对象：流程管理科、流程 Owner、项目推进人、试点部门骨干。
> 目标：用 **一条真实流程** 在系统里走完「定范围 → 接战略 → 建架构 → 定权责 →
> 立制度 → 画流程 → 配表单/工时 → 盯绩效 → 固化/改善」，并留下可验证证据。
>
> 这份文档是**带练脚本**，不是产品设计稿。设计原理见
> [startup-path.md](startup-path.md)，模块定位见 [usage-guide.md](usage-guide.md)。

---

## 0. 培训前准备（讲师 1 小时，学员 0.5 小时）

| 准备项 | 内容 | 放在哪里 |
|---|---|---|
| 一条真实流程 | 选痛点明确、跨岗位、能算清结果的一条 L3；不要选整条价值链 | 学员自己准备 |
| 流程 Owner | 有且只有一个，能对结果负责 | 组织与人员 → 治理角色 |
| 发起人/赞助人 | 能拍板资源和范围 | 同上 |
| 年度目标 | 目标值、基线、责任人、来源 | 战略目标 |
| 现有制度/SOP | 至少一份能发布的文件 | 交付物与模板库 |
| PCF 参照 | 知道这条流程大致对应 PCF 哪一段 | PCF 分类框架 |

**培训纪律**：所有「完成」必须有证据；没有证据的步骤只能标「未验证」，
不能为了凑进度打勾。

---

## 1. 先认识两条主线（10 分钟）

| 主线 | 是什么 | 用在哪 | 不要拿它做什么 |
|---|---|---|---|
| **九步启动路径**（开始使用） | 新工厂/新体系从 0 到 1 的上线主线 | 第一次建体系、培训 | 不替代单个改善项目 |
| **五阶段项目工作台**（五阶段标准工作流 → 项目工作台） | 一个改善项目的阶段门与步骤闭环 | 具体项目推进 | 不是方法手册，也不跑日常业务 |
| **24 步方法手册**（五阶段标准工作流 → 五阶段步骤） | 全公司共用的标准动作、交付物、工具 | 查方法、培训 | 不记录项目状态 |
| **流程执行** | 已建模流程的运行时 | 上线后跑实例 | 不管理改善项目进度 |

一句话：**九步管「第一次建体系」，五阶段管「一个改善项目」，流程执行管「上线后的业务」。**

## 2. 九步带练

每一步都按「页面路径 → 填什么 → 交什么证据 → 常见错误」执行。

### 第 1 步：立项定界

**页面路径**：企业流程地图 → 选 L3 → 以此流程立项；组织与人员 → 治理角色；
流程项目组合 → 新建项目。

**填什么**：

- 试点流程：只选 1 条 L3，写清起点、终点、不做什么；
- 负责人：1 个 Process Owner；
- 发起人/赞助人：1 个；
- 停止条件：什么情况下停止，不要写成「看情况」。

**证据**：试点流程有 Owner；至少 1 个治理角色；项目有发起人。

**常见错误**：一上来选整条价值链；Owner 写成部门；没有停止条件。

**练习**：在流程地图里找到你的 L3，截图它的 Owner 和优先级得分。

---

### 第 2 步：战略与现状基线

**页面路径**：战略目标 → + 新建目标 → 承接/选流程。

**填什么**：

- 目标名称：赢什么（例：采购需求端到端周期缩短 50%）；
- 目标值：可量化（14 天 → 5 天）；
- 现状基线：当前真实值，不是拍脑袋；
- 责任人、来源（年度经营计划/会议纪要）；
- 把目标挂到试点流程（承接）。

**证据**：目标有责任人和目标值；有现状基线；已挂到流程。

**常见错误**：只有目标值没有基线；目标挂在 L1 但没有说明对 L3 的影响。

**练习**：写一条「目标值 + 基线 + 责任人」齐全的目标卡。

---

### 第 3 步：流程架构设计

**页面路径**：企业流程地图 → 1+3+10 建架构 / 新建流程；PCF 分类框架 → 对照；
流程设计器 → 权责。

**填什么**：

- L1 价值链 → L2 流程类别 → L3 流程；必要时拆 L4 活动；
- 每个节点：名称、Owner、责任部门、边界说明；
- PCF 映射：这条 L3 对应 PCF 的哪一段；
- RACI：每个关键事项恰好 1 个 A（最终负责），R/C/I 可以多个。

**证据**：L1/L2/L3 都有节点；试点 L3 已映射 PCF；每个事项恰好 1 个 A。

**常见错误**：把组织架构图当流程地图；一条 L3 名称和 PCF 完全对不上；
一个事项两个 A。

**练习**：给试点 L3 写出「起点、终点、上游、下游、3 个关键事项」。

---

### 第 4 步：制度与授权设计

**页面路径**：交付物与模板库 → 流程标准文件 → 新建 SOP；
授权矩阵 → + 新建规则。

**填什么**：

- SOP：标题、类别、适用范围（组织/法人/工厂/产品族）、版本、正文文件；
- 授权规则：事项、A/B/C/D 类别、风险等级、金额上限、审批角色、
  例外路径、审批证据、依据文件；
- 例外：原因、范围、有效期、审批人。

**证据**：至少 1 份生效 SOP；至少 1 条生效授权规则，含审批人/例外路径/证据。

**常见错误**：授权规则只写「经理审批」，没有金额/风险分级；SOP 没有生效版本；
例外没有失效日期。

**练习**：为「采购需求提报」写 1 条金额分级审批规则。

---

### 第 5 步：流程 / 表单 / 工具设计

**页面路径**：流程设计器 → 模型（泳道、节点、连线、校验、发布）；
流程执行 → 表单与规则（表单、分支规则、节点分派、任务时限）；
方法论工具箱 → 按问题找工具。

**填什么**：

- L4 节点：名称、角色、时限、控制点、输入/输出；
- 表单：字段名、类型、是否必填、选项；
- 分支规则：节点、条件（字段/运算符/值）、目标节点、优先级；
- 节点分派：候选角色、限定组织、默认处理人、节点时限/升级；
- 工具：从工具箱选 1–2 个，绑定到节点或步骤。

**证据**：至少 1 份表单；表单/规则/工具至少绑定 1 项；模型校验通过。

**常见错误**：表单字段和规则条件对不上；规则目标不是该节点的出边；
所有节点都进公共队列；一次绑 10 个工具。

**练习**：给试点流程配 1 张表单 + 1 条分支规则 + 1 个节点分派。

---

### 第 6 步：工作量测量

**页面路径**：运营监控 → 工作量。

**填什么**：

- 观测方法（秒表/抽样/历史数据）；
- 作业分解、观测次数、评定系数、宽放；
- 标准工时卡、当月产能记录。

**证据**：至少 1 条已验证标准工时；至少 1 条当月产能记录。

**常见错误**：只测一次就发布；用标准工时扣个人；没有宽放和评定。

**练习**：对一个 L4 活动做 5 次观测，登记标准工时。

---

### 第 7 步：试运行与绩效监测

**页面路径**：流程执行 → + 启动流程 → 认领任务 → 填表单 → 完成并推进；
运营监控 → KPI / 异常台账。

**填什么**：

- 启动实例：选已发布模型、关联项目、可选节点处理人；
- 任务处理：填表单、写处理意见、登记实际工时、按规则或手动选择下一步；
- KPI：公式、目标值、红黄绿阈值、责任人、数据点；
- 异常：类型、严重度、责任人、期限、处理结果。

**证据**：至少 1 个完整实例跑通；1 张完整 KPI 卡 + 数据点；异常闭环。

**常见错误**：模型没发布就启动；运行中改模型期待影响已启动实例；
KPI 没有责任人或数据源。

**练习**：完整跑一个实例，记录「节点 → 表单值 → 规则命中 → 下一节点」。

---

### 第 8 步：评审与固化

**页面路径**：流程设计器 → 校验 → 提交评审 → 发布；
交付物与模板库 → 流程标准文件 → 版本生效；
组织与人员 → 培训/权限记录。

**填什么**：

- 发布说明、版本号、回退方案；
- 培训记录、权限清单；
- 评审结论（通过/有条件通过/打回）和证据。

**证据**：至少 1 条 L3 已发布模型；有生效制度/SOP 支撑；培训/权限记录齐全。

**常见错误**：只发布模型，不更新 SOP；没有回退方案；培训记录补签。

**练习**：走一次发布，写清「发布什么、谁批准、怎么回退」。

---

### 第 9 步：改善与复制

**页面路径**：运营监控 → 红黄指标转改善；流程项目组合 → 项目；
流程设计器 → 变更申请；交付物与模板库 → 治理待办；流程卡 → 单流程 360。

**填什么**：

- 改善项目：来源 KPI/异常、目标、范围、Owner；
- 变更单：改什么、影响谁、验证方式；
- 新版本：发布、基线、知识条目；
- 复制资产包：哪些组织可复用、差异参数是什么。

**证据**：至少 1 个改善项目；1 张已应用变更单；无未闭环治理待办。

**常见错误**：改善项目不从红黄指标来；变更没有影响分析；复制时把参数写死。

**练习**：从一张红黄 KPI 卡发起一个改善项目，并写出复制条件。

## 3. 五阶段工作台怎么用（项目推进时）

九步是「建体系」的主线；具体改善项目立项后，在
**五阶段标准工作流 → 项目工作台** 推进：

| 阶段 | 当前阶段要回答 | 退出门槛（示例） |
|---|---|---|
| 1 识别与优先级排序 | 改善什么、为什么是它 | 范围/目标基线/立项决策/依赖 |
| 2 诊断与根因分析 | 根因是否被证据支持 | 两类证据/影响范围/双方确认/遗留问题 |
| 3 方案设计与选择 | 改什么、为什么选它 | 方案比较/风险回退/试点口径 |
| 4 试点与推广落地 | 怎么验证后放大 | 试点结果/推广培训/遗留关闭 |
| 5 运营监控与持续改进 | 怎么保持并触发下一轮 | 基线控制限/监控责任/复盘周期 |

操作顺序：

1. 选项目 → 首屏看「当前阶段」；
2. 点步骤卡「更新状态 / 证据」：填目标、输入、处理、输出、验收证据、责任人、下一步；
3. 状态用六态：未开始 / 进行中 / 待验证 / 已满足 / 受阻 / 需决策；
4. 待验证必须有接收方；受阻必须有原因/责任人/预计解除；需决策必须有选项/决策人/时限；
5. 右侧门槛逐条更新，**标记满足前必须填证据**；
6. 所有关键门槛满足后，「进入下一阶段」才可用。

**常见错误**：把「已填写」当「已满足」；没有接收方就自己验收；门槛填「已完成」
不填证据。

## 4. 端到端案例：采购需求提报（讲师演示）

| 步 | 操作 | 结果 |
|---|---|---|
| 1 | 地图选 L3-032 采购需求提报 → 立项 | 项目 PRJ-…，Owner 陈经理 |
| 2 | 战略目标：14 天 → 5 天，基线 14 天，挂到 L3-032 | 目标卡 |
| 3 | 地图补 L1-03 / L2-003；PCF 映射；RACI 唯一 A | 架构 + 权责 |
| 4 | SOP《采购需求提报规范》生效；授权规则：≤1 万主管批，>1 万经理批 | 制度 + 授权 |
| 5 | 设计器画 n1 申请 → n2 校验 → n3 审批；表单：申请人/金额/理由；规则：金额>1 万走经理 | 模型 + 表单 + 规则 |
| 6 | 观测 n1 标准工时 20 分钟，n3 30 分钟 | 工时卡 |
| 7 | 启动实例，n1 填 8000 元 → 规则走主管；再跑 15000 元 → 走经理 | 两个实例 |
| 8 | 发布 V1.0；SOP 生效；培训/权限记录 | 发布包 |
| 9 | KPI 采购周期红转黄；转改善项目；变更单调整审批阈值 | 改善闭环 |

## 5. 培训考核清单（可打印）

- [ ] 能说出九步启动路径与五阶段工作台的区别
- [ ] 能独立建一条 L3，并指定唯一 Owner
- [ ] 能写一条「目标值 + 基线 + 责任人」齐全的目标
- [ ] 能配一张表单和一条分支规则，并说明规则优先级
- [ ] 能跑通一个实例，解释「表单值 → 实例变量 → 规则 → 下一节点」
- [ ] 能说明待验证/受阻/需决策三种状态的必填字段
- [ ] 能区分项目交付物与流程标准文件，并说出「晋升」流程
- [ ] 能说明为什么「看流程」从战略目标进入流程卡，而不是直接改流程
- [ ] 能说出附件预览/在线编辑/分发签收的边界（见附件文档）

## 6. 课时建议

| 形式 | 时长 | 内容 |
|---|---|---|
| 理论 | 2 小时 | 两条主线、模块定位、证据口径 |
| 演示 | 2 小时 | 采购需求提报端到端 |
| 带练 | 4 小时 | 学员用自己的流程走完 1–5 步 |
| 复盘 | 2 小时 | 走完 6–9 步、互评证据、答疑 |

**讲师提醒**：不要从「功能菜单」讲起，从「你现在要回答哪个问题」讲起；
每讲一个页面，都让学员指出「它不做什么」。
