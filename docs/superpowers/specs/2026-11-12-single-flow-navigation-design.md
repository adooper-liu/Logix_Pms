# 三入口主线与单流程开发环境设计

## 1. 目标

收敛一条唯一、清晰、可追踪的业务主线，方便逐页优化和定位问题；同时让新部署的测试/开发环境自动只带一条干净流程。

这不是删除生产能力，也不是把系统改成单入口。工作台的三个入口必须保留：

1. 流程框架
2. 一条流程
3. 一个项目

所有页面源码和生产业务能力继续保留。页面按照主线逐个优化、逐个挂载；完成一个页面后，再决定下一个页面如何接入。

## 2. 关键边界

### 2.1 生产能力不收缩

生产环境的 ORM、API、服务、权限和页面代码必须继续支持真实生产形态，包括多条流程、多个项目以及流程与项目之间的真实关联。

“只保留一条流程”只适用于测试/开发环境的初始化数据数量，不得写成生产业务规则，不得在生产代码中写死唯一流程或 `L3-032`。

生产部署仍建议：

```text
SEED_ON_STARTUP=false
ALLOW_DEV_SECRET=false
```

生产流程由管理员和业务人员通过正式页面/API维护。

### 2.2 测试/开发环境使用当前数据库

不新增测试数据库，不新增独立数据库架构。新部署的测试/开发环境在现有数据库初始化流程中自动灌入一条流程；当前开发数据库通过一次备份后重建达到同样状态。

测试/开发环境保留：

```text
L1-03 采购供应
└── L2-003 采购供应
    └── L3-032 采购需求提报
        ├── L4-201 需求发起与归集
        ├── L4-202 需求汇总与归并
        ├── L4-203 预算占用校验
        ├── L4-204 需求审批
        ├── L4-205 采购计划生成
        └── L4-206 计划回退与修改
```

并保留该流程需要的一个项目及必要的模型节点、连线、表单、规则、执行实例、任务、KPI、RACI 和授权等关联数据。

保留基础参考数据：

- 用户
- 组织
- 岗位
- 标准工作流模板
- 方法论工具
- 步骤契约和交付物定义
- 基准框架、分类和指标目录

不保留其他流程、其他项目或仅用于填充界面的跨流程演示数据。

## 3. 主线原则

### 3.1 工作台三个入口不变

```text
工作台
├── 流程框架
├── 一条流程
└── 一个项目
```

三个入口是三种起点，不是三套互相分裂的系统：

- 流程框架用于建立和识别 L1–L4 目录；选定 L3 后进入该流程主线。
- 一条流程用于沿同一个 `process_id` 查看和处理流程相关内容。
- 一个项目用于推进改善项目；项目有明确流程关联时回到该流程主线。

### 3.2 页面逐个优化、逐个挂载

历史页面不删除。当前页面是否挂载，是当前产品主线的发布选择，不代表页面永久废弃。

优化顺序由后续逐页确定；每个页面完成后必须说明：

- 上游从哪里进入；
- 使用哪个流程/项目上下文；
- 页面当前主题是什么；
- 产生什么结果或证据；
- 下一步去哪；
- 测试环境中如何用 `L3-032` 复现。

第一阶段可以先聚焦流程资产的概览、阻断和下一步；其他主题不提前铺开。后续按需恢复，不一次性把全部历史页面接回主线。

### 3.3 流程上下文

`process_id` 统一表示 L3 流程。若从 L4 活动进入，先解析所属 L3；需要保留活动定位时使用独立的 `activity_id`，不能让 `process_id` 在 L3/L4 之间变义。

项目当前模型使用单个可空 `process_id`，因此当前主线按“一项目一条主流程”处理。未来若扩展多流程项目，必须显式选择流程，不能自动取第一条。

## 4. Seed 实施原则

开发/测试 seed 通过现有 `seed_if_empty` 启动路径选择单流程集合；生产 bootstrap 不灌演示业务数据。

单流程 seed 只改变开发/测试数据集合，不改变 ORM 模型、API 契约、服务层的多流程能力。代码中可以有开发 seed 的保留代码集合，但生产业务逻辑不得依赖测试编码，也不得拒绝第二条流程。

当前 seed 还必须保证清理列表覆盖流程业务关联表；否则旧数据残留会在重建时触发唯一键冲突。重建前必须备份当前数据库，重建后核对保留流程、项目、关联数据和基础参考数据数量。

## 5. 验收标准

### 数据

- `process_arch` 只包含上述 9 个节点；
- `project` 只有关联 `L3-032` 的一个项目；
- 流程节点、连线、表单、规则、执行实例、任务、KPI、RACI 和授权数据只属于保留流程；
- 用户、组织、岗位、工作流模板、工具和基准框架仍存在；
- 数据库有重建前备份。

### 生产能力

- 生产模型和 API 没有“只能一条流程”的判断；
- 生产部署不依赖 `L3-032` 或单流程测试数据；
- 页面源码和未挂载页面继续保留。

### 主线

- 工作台三个入口保留；
- 页面可以后续一个个优化、一个个挂载；
- 当前测试/开发数据只让一条流程进入页面，便于定位具体节点问题。

## 6. 本轮范围外

本轮不做：

- 前端导航框架重写；
- 新增测试数据库；
- 删除页面源码、API、ORM 模型或生产能力；
- 将所有页面一次性改完；
- 把项目多流程关联提前扩展成新的数据模型；
- 用单流程测试数据替代生产数据模型。
