# 资产页单主题收敛设计

## 意图

让现有「流程资产」入口只回答一个问题：**当前流程能否生成资产包；如果不能，最先补什么。**

当前页面同时平铺资产产出、流程经营状态、Gate 5 责任、绩效/指标、表单/规则和证据主张，导致多个区块同时宣称“下一步”，用户无法判断优先动作。

## 目标

- 首屏只保留资产生成结论、关键阻断和唯一下一步；
- 将 Gate 5 作为资产生成的一个关键阻断来源，不让它取代资产页主线；
- 经营状态、Gate 5 活动明细、生成就绪度和专家明细放入后续主题区/折叠区；
- 保留现有 API、阻断事实、办理入口和后端口径；
- 任意 L3 可用，L3-032 只作为可选烟测；
- 前端不计算新状态、不维护枚举映射、不写业务事实。

## 非目标

- 不新增资产页之外的责任页面；
- 不修改 Gate 5 readiness 或资产 readiness 后端规则；
- 不自动写 Owner、RACI、NodeAssignment 或责任接受；
- 不改变流程经营周期、Gate assessment、模型发布和运行实例；
- 不删除资产关系、证据、诊断、日志、资产包等现有能力。

## 方案

资产页采用一个首屏结论区和后续明细区：

```text
流程资产
├── 首屏：能否生成资产包
│   ├── 当前结论
│   ├── 关键阻断（按后端优先顺序）
│   └── 唯一下一步主动作
└── 后续：明细与专家核对
    ├── 资产生成就绪度
    ├── Gate 5 责任闭合
    ├── 流程经营状态
    └── 关系 / 证据 / 资产包明细
```

## 状态与文案

首屏主结论只使用资产 readiness 后端返回的 `can_generate_draft`、`blockers` 和 `next_action`：

- 可生成：`可以生成资产包草稿`；主动作 `生成资产包草稿`；
- 不可生成：`暂不能生成资产包`；主动作使用第一条可办理阻断的动作；
- 只读用户：显示阻断和下一步，但不显示写入按钮；
- Gate 5 仅作为阻断明细显示，使用业务中文标签；内部 code 不作为主文案。

若资产 readiness 与 Gate 5 readiness 同时存在，资产 readiness 决定首屏主结论；Gate 5 不能单独覆盖资产 readiness 的主结论。

## 交互

- 阻断的办理按钮继续使用现有 `asset.go` 上下文跳转；
- Gate 5 责任接受说明继续在 Gate 5 明细中打开，不在首屏自动提交；
- 首屏只提供一个主动作；其他阻断动作收进明细区，避免多个按钮争夺主线；
- 页面切换仍由 `pageShell` 管理，视图不直接手写三栏/目录壳。

## 验收

机制验收只使用通用合成 L3/L4 和前端结构测试：

- 首屏存在资产生成结论、阻断和唯一下一步；
- Gate 5、经营状态、生成就绪度不在首屏同时平铺为多个主线结论；
- Gate 5 仍可在后续区查看，且办理上下文保留；
- 资产 readiness 的主结论优先于 Gate 5 的明细状态；
- 只读角色不出现写入主动作；
- 无 L3-032 生产代码分支；L3-032 仅可选烟测；
- API、后端数据、模型发布、实例和 Gate 状态均不改变。

## 实施边界

预计只修改 `web/js/views/asset.js`、必要的共享 Gate 5 展示组件和 `tests/test_frontend_structure.py`；不新增后端接口，不新增数据库迁移。完成后运行前端结构测试、`scripts/check.py`，并使用当前代码做实际页面复核。
