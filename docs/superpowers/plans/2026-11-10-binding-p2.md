# 经营绑定 P2：岗位覆盖度与岗位责任书 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: 用户选择原位实施时用 superpowers:executing-plans task-by-task；选择分代理实施时用 superpowers:subagent-driven-development。实施方式待用户确认。每步用复选框记录。不得自动提交、合并、推送；完成验收后另获用户授权。

**Goal:** 从现有岗位、活动责任与原工作量生成可核对的岗位覆盖度，以及可追溯、可版本和评审的岗位责任书。

**Architecture:** 岗位沿用 Position，活动沿用 L4 ProcessArch，RACI 保留治理角色原来源，不建岗位责任平行主库。先形成只读覆盖度与责任书预览，再按既有方案 A 扩 ProcessDocument 的主体作用域；复用 ProcessDocumentVersion、compile_manifest、CompiledAssetComponent、存储与原审批状态机。工作量沿 workload.summary，不复制公式；覆盖度与正式产物使用的模型身份明确区分。

**Tech Stack:** FastAPI、SQLAlchemy 2、Alembic、Pydantic、原生 ES 模块、pytest、Playwright；零构建。

**Spec:** docs/process-binding-dev-plan.md §4；docs/process-operating-binding-model.md §2、§4.1/4.4/4.5、§6.6、§7。本文将原开发计划中误写的“产物容器 §6.5”校正为 §6.6。新增产品决定：2026-11-10 用户确认 P2 先明确“这个岗位负责什么”；职级/能力等级在后续工作量表环节实施，回答“需要什么能力、配置多少人”。

## Global Constraints

- 基线 main@307520a；实施另建隔离工作树/分支，不修改正在使用的业务数据库、不复制根 .env、不接管现有服务。
- P2主体到岗位，不止部门职能、不按个人建岗；Position 不加职级/能力字段，不按高级/基础复制职责。实际职责授权不同的主管/专员等仍明确区分。
- 后续工作量表必须承接职级/能力、任务承接条件和人数配置；本片仅消费现有岗位级工时/产能，不预先发明能力效率系数。
- 不改三类型唯一目录、流程八阶段导航、项目五阶段；不做 P3 员工手册/关键过程矩阵、P2′三档完整性硬门禁、P4目标类型、个人绩效或批量导出。
- RACI 仍通过 GovernanceRole→有效成员→User.position_id 推导；不新增 role→position 第二套维护关系。历史 MATTER 只列流程事项，不猜活动、不计活动职责或工时。
- 覆盖度是诊断，只读、无隐式 baseline/freeze/审计写入。无绑定是缺口，不是零职责证明；无产能时负荷率 null，不返回0冒充闲置。
- 权限沿现有 org_access 与来源领域规则；ADMIN/MANAGER 可管理，其他登录用户只读其可见来源，不因岗位/主管名称授系统权限。
- 中文枚举标签由后端输出；时间 UTC，纯日期不 new Date；页面用 pageShell，首屏结论/缺口/下一步，明细后置，帮助 tipHelp、次级 foldCard。
- schema 一条 Alembic；alembic.ini 保持 ASCII。历史文档回填 PROCESS；存在岗位/角色文档时 downgrade 明确拒绝，禁止删数据回退。
- 版本只追加不覆盖；正式模型/固定绑定与现状诊断分开。未固定或变化的来源只能预览/草稿，不把岗位责任书生效当组织授权充分或业务效果成立。
- 原文档状态机 DRAFT→IN_REVIEW→APPROVED→EFFECTIVE 复用；本片不新增独立审批引擎或擅定组织职责分离政策。
- 每任务先读当前文件、测试 RED→GREEN；提交前 check.py；后端 pytest、前端 verify_frontend.py、schema alembic check，失败/跳过/未验收边界明确记录。

## Review Focus

1. 角色无人、成员无岗位/停用、跨多个岗位、受限成员：不得把过滤后剩余一人误认唯一岗位，不泄露姓名/其他岗位/备注。
2. 一个活动多个节点、多个角色或仅 NODE/MATTER 责任：活动/需求不得重复，NODE只归其明确节点映射，MATTER不猜活动。
3. 未发布最新工作版与已发布版本不同，或成员/指标/标准/资源变化：预览注明身份，旧产物保留不变，旧hash生成/流转409。
4. process_id可空后旧文档消费链：岗位责任书不能充当任意流程SOP、章程、资产包、诊断证据或项目晋升来源，旧PROCESS行为不退化。
5. 同页换岗位/月份/版本、旧弹窗/延迟响应与重复提交：不覆盖新对象、不用旧预览生成、不重复开版本，失败保留原输入。
