# P3a 员工作业手册 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 员工能看出哪些步骤归自己、该打开哪一版依据、遇到例外该按哪条原规则处理；系统不知道的，明确说不知道。

**Architecture:** 手册按 POSITION/ROLE 从原发布模型与原职责编译，不使用实际工时推导执行责任。复用 binding_readiness 的映射和 PERFORMANCE 门禁、role_position 归位、ProcessDocument 版本状态机与附件存储。新增手册编译与安全来源投影，不复制原审批或就绪度算法；不解析附件生成未经确认的指令。

**Tech Stack:** FastAPI、SQLAlchemy 2.0、原生 ES 模块、pytest、Playwright。

**Spec:** docs/process-binding-dev-plan.md §P3a（含已确认验收主线）；docs/process-operating-binding-model.md §4.2、§7。

## Global Constraints

- 岗位节点责任与 RACI-R 是两种显式来源，分别标注，不互相冒称；A/C/I 仅列协作，不生成执行步骤。节点级 R 优先于活动级 R；同活动不同岗位节点不得混入。
- 仅有工时记录或标准工时不推导作业归属。任务定义岗位是活动级任务条目，保留任务身份，不凭顺序猜模型节点。
- 只用原发布模型身份；草稿缺口可预览；固定来源身份可核对才生成草稿。正式评审/批准/生效须 PERFORMANCE 与作业依据同时通过。
- 说明正文来自原节点/任务描述或适用生效标准文件。无说明与无明确例外依据均明示缺口，不猜 A 为异常接收人，不把普通出边当例外规则。
- 固定文件版本主键/checksum/作用域与原条款；历史不静默换链。附件不存在不冒称可打开；所有预览/历史/下载与来源直链重查原范围和当前范围。
- 沿既有 pageShell、单主题 section、foldCard、tipHelp。枚举标签由后端下发，无构建工具。
- 无 ORM 字段变更，HANDBOOK 仅补字符串枚举；不引入新主数据、P3b、职级/能力人数配置或业务库升级。本片不自动提交或公开发布。

## Review Focus

- 同活动两个节点分属不同岗位；仅 A/C/I 的角色与历史工时不变作业责任。（Task 1）
- 文件升版/停用/权限变化：历史固定链接不改，正式流转失败，受限正文不泄露。（Task 2/3）
- 普通工作版不影响发布作业；原发布绑定改变必须重新固定和编译。（Task 1/3）
- 岗位/角色切换迟到响应、重复提交、通用文档或资产接口绕过。（Task 3/4）
- 空手册、缺文件、缺说明/例外、非法主体/跨流程关系不判绿；流程默认仅标继承。（Task 1/2）
