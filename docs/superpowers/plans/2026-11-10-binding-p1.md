# 经营绑定 P1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans task-by-task. 用户已要求按原计划继续；实施时不自动提交/推送/合并，验收后用户另行授权提交并本地合入 main，不推送远端。

**Goal:** 原RACI增加活动/节点作用域，活动引用原资源，原模型发布/冻结保留绑定快照并可核对变化。

**Architecture:** 沿原治理服务和设计器绑定模块增量；资源只建引用表，不复制源主数据。快照服务读取原来源并计算规范hash，冻结内容不可被后续绑定修改重写。绑定查询继续唯一输出就绪与一致性，模型发布仍不增加硬阻断。

**Tech Stack:** SQLAlchemy 2、Alembic（单迁移）、FastAPI/Pydantic、原生ES模块、pytest/Playwright。

**Spec:** docs/process-binding-dev-plan.md §3；docs/process-operating-binding-model.md §6.1–6.3、§7。

## Global Constraints

- 基线df508db；独立worktree-binding-p1。旧matter保留，不猜映射；scope_key服务生成并回填MATTER:。
- 原RACI写权限MANAGER+不放宽；资源维护同权限。CurrentUser只读，来源继续范围校验。
- 一条迁移：RACI作用域/替换唯一约束、activity_resource_link、binding_snapshot。alembic.ini保持ASCII。
- ACTIVITY优先scope，node仅锚点；仅node才NODE:，无两者仍MATTER:。
- 发布/冻结与绑定写共享流程锁；同作用域最多一个A，数据库部分唯一索引兜底。降级遇活动作用域或资源/快照数据先拒绝不丢数据。
- 模型已有binding_snapshot时永不覆盖；冻结后重复请求不刷新旧绑定，历史正式无快照不事后认证。发布冻结版本仅在绑定内容有变时要求新工作版；原本已失效且未变内容保留STALE但不增加发布门禁。
- 快照与就绪分开：历史无快照/升版后新增变更PENDING_CONFIRM，删引用或源失效STALE，一致CONFIRMED；不是业务成功结论。
- 资源源对象缺失/停用明确STALE，不用于就绪；外部设备量具只引用key，不能造实物核验。
- 中文枚举后端，UTC；pageShell/foldCard/tipHelp；不提前P2产物或P2′门禁。
