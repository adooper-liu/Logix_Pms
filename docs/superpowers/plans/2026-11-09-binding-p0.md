# 经营绑定 P0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在原设计器只读展示 L4 活动四绑定来源、缺口与节点角标，不改变现有写入或发布门禁。

**Architecture:** 单一后端查询服务读取当前设计快照及原领域对象，聚合活动与节点就绪度。设计器通过 ctx 接入绑定模块，批量绘制 marker；前端不判定业务就绪度、不维护中文枚举。原 asset-readiness 与目标级 alignment 保持原用途，不将活动级算法复制到它们。

**Tech Stack:** FastAPI / SQLAlchemy 2 / Pydantic / 原生 ES modules / bpmn-js / pytest / Playwright。

**Spec:** `docs/process-operating-binding-model.md` §2、§7.1；`docs/process-binding-dev-plan.md` §2。

## Global Constraints

- P0 只读：不做任何写入；不改 `ProcessDocument` / `RaciAssignment`；不把绑定状态写进数据库。
- 四面状态为 `READY` / `PARTIAL` / `MISSING` / `CONFLICT`，中文标签后端下发。
- 当前 RACI 无活动作用域，流程事项不猜成活动 A，因此 TEAM 不能 READY；留给 P1。
- 当前设计快照优先；无版本读原运行节点，但不补建基线。映射只用当前版本/历史空版本，关系优先于兼容指针。
- 默认估计 0 不证明明确设计时长；估计与已验证工时分开展示；流程继承最多 PARTIAL。
- 只给四面全空节点红色，部分黄色，四面齐全绿色；冲突单列且不能绿色。
- 页面沿用 pageShell；帮助用 tipHelp，次级明细用 foldCard；不引入构建工具。
- 实施阶段不自动提交/推送/合并；2026-11-10用户随后授权提交并本地合回main，不推送远端。

## Review Focus

- 设计草稿与发布模型不同：不能拿发布节点给草稿画伪绑定，保存后要刷新。
- 多对多映射、旧版本关系、跨流程活动：只选当前有效关系，异常显式冲突，不覆盖或泄露外部数据。
- 流程级 KPI/RACI/默认表单/培训：标明继承或未到活动，不能直接判 READY。
- 过期/未生效文件、受限组织引用、缺来源证据：不能据存在行洗绿或泄露引用。
- 换流程/退出页面的迟到响应与重挂画布：旧响应不得覆盖新状态，marker 不得残留，不能触发保存。
