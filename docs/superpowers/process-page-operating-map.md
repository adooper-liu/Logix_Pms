# 流程经营页面职责映射

> 版本：v1.0
>
> 依据：[流程经营系统规格](superpowers/specs/2026-11-13-process-operating-system-design.md)。
>
> 目的：在 Task 2/3 通用经营契约和 L3-032 样本演练基础上，决定后续页面逐个挂载的业务依据；本文件不删除页面、不改变导航、不授权一次性重写。

## 1. 分类规则

| 分类 | 判定标准 |
|---|---|
| `mainline` | 直接帮助用户完成当前 Gate，输出事实/证据/决策，并提供下一步 |
| `projection` | 展示同一流程事实的特定视角，不拥有第二套事实口径 |
| `backend-support` | 维护主数据、配置、权限、规则、接口或扫描，不要求业务用户先理解 |
| `learning/reference` | 方法、培训、术语、行业参考和工具知识，不直接决定流程状态 |
| `defer` | 当前存在源码，但尚未证明对 0→1 主线有独立必要输出 |

## 3. 当前系统的关键重复风险

后续实现必须验证并避免：

1. `ProcessArch` 状态、流程卡状态、资产就绪度和经营周期 Gate 各自计算一套流程状态；
2. KPI 状态在 monitor、dashboard、project 和前端各自重新判断；
3. RACI、Owner Role、岗位责任和任务分派分别表达同一责任却不互相校验；
4. 项目阶段门与流程 Gate 互相覆盖，导致项目“通过”自动变成流程“上线”；
5. 工具箱结果、SOP、交付物和员工手册重复保存同一工作产物；
6. SCOR/APQC 映射既被当作分类参考，又被误当作企业流程状态；
7. 单流程 Seed 的数据数量被错误变成生产业务约束。

## 4. 第一批主线候选

在通用经营契约稳定后，第一批主线候选不按历史菜单顺序，而按 L3-032 0→1 缺口选择：

```text
工作台
→ 流程框架/流程清单
→ 目标与结果
→ 边界与架构
→ 现状与问题
→ 设计与控制
→ 组织与资源
→ 工作指引与能力
→ KPI/工作量/数据
→ 试点准备
```

`asset` 作为流程经营摘要入口，负责显示当前 Gate、阻断、证据和下一步；它不复制专家页的明细。

## 5. 反推结果的使用规则

本表只作为下一轮页面决策输入，不自动改变当前挂载：

- 只有经过业务任务、输出证据、下一步和样本测试确认的页面才加入主线；
- 只读摘要回到原事实来源，不在摘要页编辑第二套数据；
- 后台页面通过主线缺口按钮进入，必须保留 `process_id`/`project_id` 上下文；
- 延后页面源码保留，等对应 Gate 任务明确后再评估；
- 页面合并必须先证明原页面使用同一事实来源且用户任务不冲突。
