# 主任务实施 Brief：三类型、八阶段与主体能力对齐

> M1a–M4已依次经PR#14、#16–#18合并；M5经PR#19合并9246f4e；M6经PR#20合并c3072bc；M7提交70da711经PR#21合并52bbb41，SQLite/PostgreSQL CI通过。当前M8位于feat/round-outcome-governance，范围及首个RED见§12。

## 1. 主任务与完成标准

以长期流程为主对象，将核心/支持/管理三类型、八阶段生命周期、贯穿治理及专业能力落实为可办理功能、原产物引用、责任/核验和跨环节交接；页面与语言随主体功能一起交付。

沿用[总路线](bpm-lifecycle-gap-and-roadmap.md)、[落地规格](bpm-lifecycle-implementation-spec.md)、[产品原则](bpm-product-principles.md)及原八专项，不再另建业务框架。八阶段不是新状态机，改善项目仍五阶段，治理不编第九阶段。

最终不是“菜单齐全/类型标签存在”，而是至少一条流程能明确分类与客户边界，沿八阶段在原模块完成各项作业、产物/版本/样本核验和持续反馈，三类型关系、治理保障与专业支持有真实落点。真实效果/组织采用必须业务证据，不由演示或CI代替。

## 3. 当前实施单元：M1a 分类维护与消费闭环

**具体决定（本次工程设计，非伪称过去已批准）：**

- 同一个ProcessArch增加nullable `process_type`（CORE/SUPPORT/MANAGEMENT）、分类依据、是否允许继承及分类修订号；历史全部未明确，不按PCF/名字/层级回填。

- 不改变原priority_score、流程层级、APQC参照、组织范围、运行模型或项目阶段；不建立三套目录。

**本片交付：** migration/model/schema/分类service/meta+分类写API、列表/树/详情/流程卡消费、地图分类操作与筛选、API/迁移/真实UI验证。仅类型字段存在不算完成；横向交接与组合排序依据在M1b/M3另交，不伪称本片已实现。
