# 执行层 P2 项目：补偿、版本与留存

> 来源：`docs/process-execution-gap-analysis.md` 的 P2 清单。独立项目推进。

## 范围

| 阶段 | 交付物 | 状态 |
|---|---|---|
| E1 取消后的业务补偿 | 节点补偿动作、取消时生成补偿待办、完成留痕 | 本轮实现 |
| E2 部署回滚 | 从历史已发布版本生成新的发布版本 | 本轮实现 |
| E3 实例归档与保留 | `archived_at`、按天数归档、列表默认排除 | 本轮实现 |
| E4 表单/规则版本 | 定义版本递增与实例冻结版本 | 后续 |
| E5 WORM/外部归档 | 对象存储 WORM、留存策略 | 需基础设施 |
| E6 多租户/分区/仿真 | 租户隔离、分区表、离散事件仿真 | 需独立架构评审 |

## 明确不做

- 不把「取消」等同于「补偿完成」：补偿必须有独立待办和完成人。
- 不在没有租户模型前硬加 tenant_id；会制造半成品隔离。
- 不对运行中实例做破坏性回滚；回滚只影响后续启动。

## 验收

- 取消实例后，已执行节点的补偿动作进入待办，可逐条完成；
- 回滚发布生成新版本，历史版本与运行中实例不受影响；
- 归档后默认列表不可见，详情仍可追溯。
