# bpmn-js 编辑器的行业最佳实践与差距

> 范围：流程设计器（`web/js/views/designer.js`）与相关后端模型接口。
> 目标：以 Camunda Modeler / bpmn-io 生态为参照，判断当前编辑器在**建模能力、治理、
> 协作与执行语义**上的位置，并给出可执行的优先级。
> P0 已完成「单一编辑面 + 功能对等」；P1/P2 是后续路线。

## 1. 结论摘要

- **编辑面已经收敛**：bpmn-js 是唯一画布，自研「简洁画布」已删除，不再维护两套模型编辑逻辑。
- **属性面板达到可用**：节点、连线、泳道、流程四类元素都能在右侧栏编辑；节点分派/SLA、
  负责人、类型、跨泳道移动、连线条件/概率均已落到后端模型。
- **治理链路是强项**：草稿/评审/发布/回滚、版本差异、审计、乐观并发控制、只读态与调色板
  禁用都已有，明显强于一般内部工具。
- **最大差距在执行语义**：并行网关、子流程、边界事件、事件网关、DMN 仍不支持；调色板
  刻意隐藏这些构造，属于「引擎能力」而不是「编辑器能力」。
- **次大差距在协作与复用**：没有元素评论、实时协作、元素模板库、可视化版本差异。
- **中文化与校验体验**已优于原版 bpmn-js：规则消息翻译为「问题 + 影响 + 建议」，
  错误/警告分级，问题可定位到元素。

## 3. 关键差距详解

### 3.1 执行语义（P2，后端优先）

行业编辑器（Camunda、Signavio）支持并行网关、子流程、边界事件、事件子流程、DMN。
当前后端是单令牌串行引擎，因此：

- 调色板、上下文菜单、「更改元素」菜单隐藏了并行/复杂/事件网关、子流程、边界事件；
- 导入含这些构造的 BPMN 会被后端拒绝，而不是静默降级；
- 这是**有意的正确性取舍**，不是编辑器缺陷。

要补齐，需要先做令牌引擎、并行 join/split、多 OPEN 任务、实例完成判定，再放开调色板。
不要在引擎未支持前恢复这些入口，否则会出现「画得出、跑不了」。

### 3.2 属性面板（P0 已完成，P1 深化）

已覆盖：

- 节点：名称、PMS 类型 ↔ BPMN 类型、所属泳道、负责人、作业/等待/成本/返工/审批层级/
  增值、候选角色/组织/默认处理人/时限/升级。
- 连线：标签、条件表达式、概率、删除。
- 泳道：名称、包含节点、新增泳道。
- 流程：名称、泳道概览。

P1 建议：

- 默认分支（`default` flow）选择；
- 元素说明（`bpmn:documentation`）；
- 表单/规则绑定与跳转（复用执行页现有接口）；
- 属性分组折叠，减少长侧栏滚动。

### 3.3 校验与治理（P1）

当前有 bpmnlint recommended + 后端 `validate_model`，但两套结果没有合并：

- bpmnlint 在侧栏「校验」页签，可点击定位；
- 后端校验只显示在画布下方的黄色提示，且不阻止发布；
- 缺少 PMS 业务规则：概率和、泳道归属、分派完整性、默认分支、跨泳道移交次数等。

P1 建议把后端校验合并进同一页签，统一为「错误阻止发布、警告提示」，并支持 `node_key`
定位。

### 3.4 版本与差异（P1）

已有草稿/评审/发布/回滚/审计和节点/连线级文本 diff。行业实践会提供**并排/叠加的
BPMN 图差异**。可在版本详情里用只读 bpmn-js 渲染两个版本，并给变更元素加 marker。

### 3.5 协作（P2）

当前只有乐观并发（`expected_version` → 409）。缺少：

- 元素级评论与 @提醒；
- 正在编辑/在线状态；
- 锁定或实时协同。

内部流程管理场景下，评论通常比实时协同更有价值，建议先做评论。

### 3.6 模板与复用（P2）

已有工具模板、交付物模板、标准文件变体；但没有 BPMN 元素模板（例如「采购审批」标准
节点组）和流程模板。可复用现有模板库的组织/版本能力，新增 `bpmn_template` 资产。

### 3.7 中文化与可访问性（P1）

- 业务侧栏、校验消息已中文；
- bpmn-js 调色板/上下文菜单的内置 title 仍是英文；
- 无快捷键帮助页。
可通过自定义 `translate` 模块与一个快捷键帮助弹窗补齐，成本低。

### 3.8 安全与性能（保持/观察）

- 后端已限制 XML 大小、节点数、拒绝 DOCTYPE/ENTITY；
- 前端属性值统一 `esc`，bpmn-js 以 SVG 文本渲染标签；
- 大模型（>500 节点）直接拒绝，属于明确的产品边界；如需更大规模，再考虑分页/虚拟化。

## 4. 路线图

### P0（本轮已完成）

- 删除简洁画布，bpmn-js 成为唯一编辑器；
- 节点/连线/泳道/流程属性面板；
- 泳道新增（带默认活动）、改名、跨泳道移动；
- 节点负责人、类型、泳道；
- 连线标签/条件/概率；
- 审批/移交节点直接创建；
- 调色板只读可见可折叠、自动布局保留泳道、适应画布避让侧栏；
- 后端 owner_role 与显式概率 1.0 的保存语义；
- 后端/前端测试覆盖。

### P1（2026-10-25 已完成大部分）

1. ✅ 后端 PMS 校验并入「校验」页签；发布前先校验，阻断错误；
2. ◐ 版本差异已做结构化差异（节点/连线新增、删除、字段变更）；画布叠图对比未做；
3. ✅ 默认分支（网关 default）+ 元素说明（BPMN documentation）；
4. ✅ 设计器侧列出表单/分支规则，并带流程与节点上下文跳到执行配置；
5. ✅ bpmn-js 通用文案中文化 + 「快捷键」帮助弹窗；
6. ◐ 空泳道可由 BPMN XML 保留；快照 lanes 与显式拖拽排序未做。

### P2（按业务优先级）

1. 元素评论/协作；
2. BPMN 元素模板/流程模板；
3. 令牌模拟与路径 what-if；
4. 并行网关/子流程/边界事件（先做后端令牌引擎）；
5. DMN 决策表；
6. Pool/Participant 与多组织泳道语义。

**P1 落地证据（2026-10-25）**：

- `web/js/views/designer/lint.js` 合并 bpmnlint 与 `/design/validate`，发布前阻断错误；
- `process_node.description`、`process_edge.description` / `is_default`，迁移 `f9a0b1c2d3e4`；
  导入/导出支持 BPMN `documentation` 与网关 `default`；
- 属性面板支持元素说明与默认分支；表单/规则列表带节点上下文跳转执行配置；
- `designer/i18n.js` 翻译 bpmn-js 通用文案；工具栏新增「快捷键」帮助；
- `tests/test_bpmn.py` 覆盖说明与默认分支往返。
