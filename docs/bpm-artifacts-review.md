## 4. 剩余必须进入开发计划的决定

这些不是用免责声明保留的矛盾方案，而是需要在具体实现前定值的技术/业务输入：

1. 原ProcessModelVersion怎样固定非运行版本，并与现有latest/draft/publish/rollback兼容；正式引用不可变，具体新增字段/枚举/测试未定。
2. round修订/expected_revision/幂等、项目/模型/口径范围校验、sample_refs大小与查询、NULL唯一性及事务策略。
3. 原GateAttestation扩哪些验收用途/结果，怎样指定有权审核者和证据快照；不能拿当前PASS标签包办本轮改善结论。
4. 日常KpiRecord保留当时口径/来源及修订，正式验收样本不可被原同期更新逻辑覆盖。
5. 删除/停用与证据保留、组织权限聚合、历史回填不明和个人数据保留的真实策略。
6. R3接入版本/能力范围、外部部署/命令/事件事务、启动/在途/迁移和跨库恢复，另列集成计划。
7. 试点的客户目标、风险、样本、授权、资源与验收窗口由业务批准，不由文档自行填默认标准。

未定值不妨碍总体原则确认，但阻止直接按文档“全量开工”。第一份实施计划应以薄对照的最小端到端行为及失败用例为单元，不再扩大需求。
