# 过硬演示包：简历主张 → 能点开的证据

简历正文见 [resume.md](resume.md)。

这套东西只认三条铁律：

1. **产品主链只有两条事**：把公司流程体系立起来；把一条流程改好。
2. **开始使用只有一个钟**：九个阶段、全公司计数。证据数字能点开对应记录。
3. **简历能讲的，必须是系统里能打开的。** 讲不出入口的，标成部分或没有，面试时不硬说。

没有单独的「能力地图」页，也不把五阶段、工具箱、交付物、数据治理放回侧栏。那些是步骤里的工具。

## 侧栏（现行）

**把公司流程体系立起来**

开始使用 → 十层单页 → 组织与人员 → 企业流程地图 → 授权矩阵

**把一条流程改好**

战略目标 → 流程项目组合 → 流程设计器 → 流程执行 → 运营驾驶舱

从步骤或页面里进、不占侧栏：五阶段工作流、流程卡、方法论工具箱、交付物、PCF、架构草图、数据治理。

## 一句话

Logix PMS 管流程怎么设计、谁负责、凭什么放行、改善有没有证据。

业务交易在 ERP、MES、WMS、APS、财务系统里。这里不建那些对象。

## 两套钟

| 钟 | 页面 | 数什么 | 别和谁混 |
|---|---|---|---|
| 公司办法建到哪 | 开始使用 | 九阶段全公司计数；前 8 段齐了才能首次上线；跳过不算就绪；第 9 段不挡上线 | 不是某一条试点路径的当前层 |
| 一条流程改到哪 | 流程项目组合 → 项目 | 五阶段；阶段 1 要挂流程且至少 2 项有效战略 KPI；阶段 2 根因门要绑门上的独立裁决证据 | 不替代开始使用的全公司计数 |

十层单页是某一条 L3/L4 的核对单。层的退出条件复用开始使用的证据。新建路径不造证据、不推动公司阶段。

阶段 1「L3 已绑定负责人」数的是 `level=3 AND owner_user_id IS NOT NULL`，不是地图上的负责人文字。

## 五分钟过硬演示（按这个顺序走）

1. **开始使用**  
   讲九阶段是公司钟。点当前阶段的证据数字，确认能跳到对应记录。点「L3 已绑定负责人」，地图只列出绑了账号的 L3。
2. **企业流程地图 → 对标**  
   讲统一语言：L1–L4 与 APQC 的对应。
3. **战略目标**  
   讲目标、基线、挂到流程。
4. **流程项目组合 → 打开一个改善项目**  
   讲五阶段。阶段 1 战略 KPI 门、阶段 2 根因证据独立裁决。强调这是改一条流程的钟。
5. **流程设计器 → 分析**  
   讲 PCE、等待、返工、移交、瓶颈、方法论建议。
6. **流程设计器 → 权责** 与 **授权矩阵**  
   讲 RACI 和审批规则分开。
7. **流程执行**  
   讲实例、任务、表单与规则。
8. **运营驾驶舱 → KPI / 工作量**  
   讲红黄可转改善；标准工时与产能。
9. **边界一句**  
   这是流程治理与改善系统。运单、库存、排程、总账不在这里。

## 不要说成系统做出来的

- 供应商、采购、库存、仓储、物流、运单、承运商、运费、预提、报关、EUDR
- APS 有限产能排程
- WMS、条码、Andon、立体仓
- 总账、成本核算、杜邦、本量利、标准成本差异、边际贡献
- 飞书低代码（本系统是自研 FastAPI + 原生前端）
- 预提准确率、月结天数、日产量、单柜利润等历史经营数字——只能记成项目 / KPI / 证据，系统不会自己复现
