# BPMN P2 项目：协作、仿真与执行语义

> 来源：`docs/bpmn-js-best-practices.md` 的 P2 清单。作为独立项目推进，
> 不混入业务流程改造。所有阶段都以「可回退、可验证」为前提。

## 范围

| 阶段 | 交付物 | 状态 |
|---|---|---|
| B1 元素评论/协作 | 节点/连线的评论、解决状态、作者与时间线 | ✅ 2026-10-25 |
| B2 路径模拟 | 基于已保存模型的路径枚举、概率/周期/成本 what-if | ✅ 2026-10-25 |
| B3 决策表（DMN 简化） | 决策表 CRUD 与首命中/汇总求值 | ✅ 2026-10-25 |
| B4 元素/流程模板 | 可复用节点片段与流程片段 | 后续 |
| B5 并行网关/子流程/边界事件 | 多令牌执行引擎 | 需独立架构评审 |
| B6 Pool/Participant | 多组织泳道语义 | 需组织主数据决策 |

## 明确不做

- 不在 B1/B2 阶段修改执行引擎；并行网关仍由导入校验拒绝。
- 不引入外部 DMN 引擎；先用受控的 JSON 决策表。
- 不做实时多人协同编辑（需要 CRDT/OT 与冲突合并，单独立项）。

## 验收

- 评论按流程 + 元素聚合，解决后保留历史；
- 路径模拟结果来自已发布/草稿快照，不臆造节点；
- 每个阶段单独提交，`python scripts/check.py` 与 `scripts/verify_frontend.py` 通过。
